Дата: 10 октября 2026. Документ для следующей сессии в Claude Code и для
любого, кто подхватывает проект с нуля. Читать вместе с `CLAUDE.md`,

## 1. Что это за игра

Геополитическая симуляция: 32 страны, 2026–2042, ход равен месяцу.
Игрок ведёт одну страну, остальные ведёт ИИ.

**Крючок — двухуровневая игра.** Чтобы договориться снаружи, нужно
одновременно устроить партнёра и собственную коалицию дома. У той
стороны тоже есть парламент и группы интересов. Если между тем, что
примет партнёр, и тем, что пропустят дома, нет просвета, сделки нет, и
игра прямо называет, кто именно её похоронил.

**Тон.** Игрок — глава государства, а не оператор кнопок. Неполная
информация, прогнозы вместо ответов, у каждого решения цена. Игра
соглашается с целью игрока и показывает цену, а не поучает. Формулировка
«не получилось» запрещена: называется ограничение, которое сработало.

**Ориентиры по ощущению:** Suzerain (документы, люди, разговоры),
Hearts of Iron IV (плотность и глубина при ясности), Democracy 4 (всё
связано со всем, связи видны), Crusader Kings III (персонажи и
подсказки), This Is the President (атмосфера кабинета).

## 2. Что сделано к этому моменту

### 2.1 Движок на Python (`engine/`, 26 модулей, около 5 700 строк)

Чистый Python 3.11+, без зависимостей. Все числа и тексты в `data/*.csv`
(22 таблицы). Детерминированность: один сид даёт одну партию.

| Модуль | Что делает |
|---|---|
| `state.py`, `sim.py` | состояние мира, месячный такт, сохранение и концовки через `save.py`, `ending.py` |
| `channels.py`, `valves.py` | четыре канала распространения влияния; три «клапана», чтобы у игрока всегда был ход |
| `power.py` | совокупная мощь из шести компонентов |
| `deal.py`, `package.py`, `execution.py` | сделки с двумя порогами (потолок ратификации дома, порог принятия у партнёра), сетки делимости, пакеты, график поставки |
| `groups.py`, `politics.py`, `government.py`, `policy.py` | десять групп интересов, выборы, 15 министерств с национальными вариантами, 34 рычага, четыре направления внешней политики |
| `personnel.py` | министры и послы с пригодностью к посту |
| `escalation.py` | лестница эскалации, спорные территории как переменные |
| `intel.py` | разведка, оценка чужого порога с ошибкой |
| `ai.py` | доктрины ИИ, инерция, перекос в поведении, клиенты и покровители |
| `agenda.py` | повестка, порождённая изменениями мира, а не сценарием |
| `economy.py` | ВВП, курс, торговля по партнёрам, корзина экспорта |
| `legible.py` | **договор о подаче**: наружу только деления шкалы и слова (Р-28) |
| `i18n.py` | два языка, русский исходный |
| `portrait.py`, `faces.py`, `scene.py`, `opening.py` | послойные портреты, флаги, иконки, сцены событий, первый экран |

Данные реальные: World Bank, SIPRI, V-Dem, UN Comtrade, COW
(`tools/ingest.py`). Торговля покрыта примерно на треть пар (Б-54).

### 2.2 API (`api/server.py`)

17 точек: `openings, start, strings, lang, search, dashboard, cabinet,
course, world, dossier, negotiation, package, shortlist, act, tick,
save, load`. Ответы — JSON с делениями шкалы.

**В этой сессии (Р-56):**

- Вся маршрутизация вынесена в `route(method, path, query, body)`.
  Через неё ходят три транспорта с одинаковыми ответами:
  - HTTP: `python3 api/server.py` для `web/`;
  - **процесс-спутник**: `python3 api/server.py --stdio`, одна строка
    JSON на запрос, одна на ответ. Это основной путь для десктопа;
  - `call()` для прямого вызова, проверено в Pyodide (движок поднимается
    в WebAssembly без единой правки: импорт 0,5 с, пульт 19 мс, ход 0,29 с).
- Исправлено: полосы состояния на Пульте теряли названия («с запасом»
  вместо «влияние дома»). Теперь `name`, `label`, `id` раздельно.
- `tools/audit.py` понимает новую маршрутизацию.
- Проверки `tools/check.py`: семь из семи.

Протокол `--stdio`:

```
→ {"method":"GET","path":"/api/dashboard"}
← {"code":200,"body":{...}}
→ {"method":"POST","path":"/api/act","body":{"effect":"sign","params":{...}}}
→ {"method":"GET","path":"/api/dossier","query":"code=USA"}
```

### 2.3 Интерфейс без сборки (`web/`)

Три файла (`index.html`, `app.js`, `style.css`) и материалы: флаги
(SVG), иконки, 6 региональных пулов лиц (SVG), заглушки роликов, звук
(WAV). Пять разделов (Пульт, Кабинет, Курс, Мир, Досье), два наложения
(переговоры, итог месяца), поиск Ctrl+K, два языка, адаптивный звук.
Остаётся как лёгкая показная версия.

### 2.4 Прототип для инвесторов (Claude.ai, проект «Diplomacy»)

Отдельная HTML-страница на сценарии Турции (октябрь 2026 — выборы мая
2028). Лежит в архиве передачи: `reference/investor-prototype/`. Не
связан с движком, это **макет опыта**, из которого в десктоп переносятся
решения, а не код:

- модель причин: 24 показателя, 42 связи с лагами, «откуда число»
  по клику на любое значение;
- персонажи в духе CK3: навыки, черты, перки, лояльность, секреты,
  сеть связей;
- двухуровневые договоры с полукругами парламентов обеих сторон;
- встречи как короткие диалоги, статистические слайды итогов месяца;
- кинематографический слой: свет, пыль, состояние страны (спокойно,
  напряжённо, кризис) меняет атмосферу;
- **диегетический кабинет**: стол главы государства, где каждый
  предмет — прибор (депеша, полукруги парламентов, шестигранный датчик
  мощи, трёхстрелочный циферблат отношений, лестница эскалации, колонна
  стабильности, разделители министерств, пульт голосования, штампы,
  календарь, папка разведки). 12 национальных стилей кабинета.
  Сделан в 2.5D; заказчик оценил как «бюджетно». **В десктопе это
  делается настоящим 3D** — см. `docs/ART_DIRECTION.md`.

## 3. Решение: десктоп

Целевая форма — десктопная игра с тяжёлыми материалами (порядка 3–4 ГБ).
Браузер остаётся для показа (`web/`).

### 3.1 Клиентский движок

**Рекомендация: Godot 4 (последняя стабильная, C# или GDScript).**

- Игра — это интерфейс плюс несколько качественных 3D-сцен, а не
  открытый мир. Godot силён в сложном UI (Control-узлы, темы, контейнеры)
  и даёт приличный 3D (PBR, объёмный туман, SDFGI/VoxelGI, глубина
  резкости, свечение).
- Бесплатный, без роялти, лёгкий редактор, проект целиком текстовый —
  хорошо ложится на работу с Claude Code (сцены `.tscn` и скрипты
  читаются и правятся как текст).
- Процесс-спутник на Python запускается через `OS.execute_with_pipe`.

Альтернативы:

- **Unity** — на нём сделан Suzerain, огромная база ассетов, но
  платформа с лицензионными рисками и тяжелее для работы с текстом.
- **Unreal 5** — лучший фотореализм (Lumen, Nanite, MetaHuman), но для
  игры, где 80% времени игрок читает и решает, это переплата сложностью;
  C++/Blueprints хуже автоматизируются.

Выбор — за владельцем. Всё ниже описано так, что подходит к любому из
трёх; детали даны для Godot.

### 3.2 Архитектура

```
┌──────────────────────────── десктоп-клиент (Godot) ───────────────────────────┐
│  UI-слой (Control)          3D-сцены (Node3D)            Звук                 │
│  разделы, наложения,        кабинет, переговоры,        слои по состоянию    │
│  подсказки, досье           подписание, кризис          (base/tension/crisis)│
│            │                         │                                        │
│            └──────── ViewModel (полосы, слова, события) ─┘                     │
│                              │                                                │
│                     EngineBridge (C#/GDScript)                                │
│                     очередь запросов, таймауты, перезапуск                    │
└──────────────────────────────┼────────────────────────────────────────────────┘
                               │  stdin/stdout, JSON по строке
┌──────────────────────────────┼────────────────────────────────────────────────┐
│     python api/server.py --stdio   →   route()   →   engine/*   ←  data/*.csv  │
└───────────────────────────────────────────────────────────────────────────────┘
```

Правила:

1. **Движок — единственный источник правды.** Клиент не считает
   игровые величины, не округляет и не хранит своё состояние мира. Он
   спрашивает и рисует.
2. **Клиент не видит сырых чисел** (Р-28). Если для 3D-прибора нужна
   непрерывная величина (стрелка), движок отдаёт деление; стрелка плавно
   встаёт в середину деления. Если понадобится больше точности для
   анимации — новое поле в API, а не вычисление в клиенте.
3. **Новые данные — новые точки API**, а не разбор `turn` целиком: сырой
   ответ `tick` содержит внутренние числа и наружу не идёт.
4. **Поставка Python.** Внутрь сборки кладётся переносимый интерпретатор
   (python-build-standalone или официальный embeddable-пакет для Windows,
   около 25–40 МБ) плюс `engine/`, `api/`, `data/`. Никакой установки у
   игрока.
5. **Сохранения** — в пользовательской папке ОС; клиент передаёт путь
   (нужно добавить параметр к `/api/save` и `/api/load`, сейчас путь
   жёстко `savegame.json` в корне).
6. **Портреты и флаги**: движок отдаёт ключи и пути (`/flags/IND.svg`,
   `/faces/south/f/01.svg`); клиент сопоставляет их с импортированными
   ресурсами. В десктопе SVG-заглушки заменяются нарисованными портретами
   по той же схеме ключей (`docs/ASSETS.md`).

### 3.3 Раскладка репозитория (предложение)

```
engine/ api/ data/ tools/ docs/ web/     как сейчас
desktop/                                 проект Godot
  project.godot
  bridge/EngineBridge.cs                 процесс-спутник, очередь, таймауты
  ui/                                    темы, разделы, наложения, подсказки
  scenes/office/                         3D-кабинет, 12 стилей
  scenes/vignettes/                      переговоры, подписание, кризис, присяга, речь
  art/                                   исходники (через Git LFS или внешнее хранилище)
  tests/                                 GUT или собственные прогоны
```

**Большие файлы.** Лимиты GitHub: файл до 100 МБ, репозиторий желательно
до 1–5 ГБ, Git LFS бесплатно 10 ГБ хранения и 10 ГБ трафика в месяц.
Код и данные — в git; модели, текстуры 4K, звук и видео — в LFS или
во внешнем хранилище с манифестом (путь, размер, хеш) в репозитории.
Сборки раздаются через GitHub Releases (до 2 ГБ на файл).
